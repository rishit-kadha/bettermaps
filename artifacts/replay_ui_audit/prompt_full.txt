# 6. RESET TEST

This is a critical audit.

Perform:

1. Select session A.
2. Start replay.
3. Let the trajectory accumulate.
4. Press RESET.
5. Capture a screenshot immediately after reset.

Verify visually that:

- all replay-generated paths disappear
- old trail disappears
- stale markers disappear where appropriate
- stale diagnostics disappear
- progress resets
- replay status resets
- map state resets appropriately
- no old geometry remains

Then wait several seconds WITHOUT starting another replay.

Capture another screenshot.

This is specifically intended to catch:

> RESET clears state → stale replay callback fires → old path reappears.

If the old path reappears after reset, document it as a HIGH-PRIORITY finding.

---

# 7. SESSION SWITCH TEST

Perform:

1. Run session A.
2. Reset.
3. Change to session B.
4. Capture screenshot before starting B.
5. Start B.
6. Let B render.
7. Capture screenshot.

Verify:

- no trajectory from A remains
- no session A labels remain
- no stale timestamps remain
- no old diagnostics remain
- no stale marker remains
- route/trail belongs exclusively to B
- session selector displays B
- map camera state is appropriate for B

Look especially for stale asynchronous state.

# 15. Important Finding Rules

Be precise.

Do NOT write vague statements like:

"UI could look better."

Instead write:

"Session picker bottom sheet extends beneath the Android navigation/safe-area region, causing the final row to be partially obscured."

Or:

"The reset button clears the visible polyline immediately, but 1–2 seconds later the previous replay trail reappears, indicating a stale replay callback is repopulating the trajectory buffer."

Or:

"The selected session label and metadata have insufficient horizontal separation and visually collide on the physical 1080px-wide device."

Only document things you actually observe.
